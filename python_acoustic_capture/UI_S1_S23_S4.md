# 四入口采集界面

本次修改基于 `codex/rir-repair-20260919` 的源码；旧便携 EXE 不会自动更新。

## 使用方式

- **S1-RIR采集**：选择声卡、录制通道、输出通道、测量次数和保存文件夹。开始时命名。ESS 参数默认收起。扫描过程中显示移动进度线，全部测量结束后显示结果；不在下一次扫频期间加载上次完整结果图。
- **S23-人工头语音对数据集采集**：选择 target、interferer 文件夹，设置次数和片段时长。开始时命名。默认 target-only、interferer-only、mixed 三阶段；配对与断点续采沿用原实现。更多采集方式、随机种子和索引字段在“更多设置”内。
- **S4-真实数据集采集**：选择干扰文件夹，设置每阶段时长和轮数；可选 UTF-8 TXT 语料（每行一句，可含中英文），留空使用用户提供的 19 行语料。右侧按阶段提示朗读或安静，显示声源示意图及移动进度线。每轮使用同一组提示、同一个干扰文件；下一轮换语料组和干扰素材。人工嘴不播放，佩戴者是目标源。
- **简单录制**：选择输入、通道、保存位置、时长，开始时命名；不需要配置播放源。

界面没有“大实验”创建、结束或打包入口。历史 campaign/ACQUA 文件处理模块仍保留在源码中，避免破坏已有数据和程序接口。声卡后端（真实/模拟）始终显示在顶部，防止把模拟采集误当成实采。

## S4 数据说明

每轮的三个阶段单独保存多通道原始录音到 `raw/round_NNN_<stage>.wav`，完整四秒片段保存到 `processed/`。不足四秒的尾部仍在原始文件中；手动停止也保留已录数据。

`raw/labels.csv` 同时索引原始阶段和切片，包含阶段、轮次、起止采样点、提示文本、干扰源路径、录制状态。配置和 manifest 保存受试者编号、耳机、佩戴等实验标签；通过“编辑标签”填写匿名受试者编号即可。

重要：真人 target-only 与 mixed 是两次独立朗读，**不构成逐采样配对的干净监督目标**。`strict_supervised_pair=False` 明确标记这一点。提示文本也不是经验证的逐片段转写。S4 适合真实场景评估/非配对数据；需要严格监督参考时仍使用 S23 或另外设计同时采集的参考通道。

## 卡顿相关修复与边界

- 实时回调不再发送 GUI 进度；改由声卡控制线程轮询进度。
- 播录开始前完成首次预览绘制，避免字体、坐标轴和波形初始化与音频同时竞争。
- 动画只更新游标，不再每 80 ms 重画完整波形图。
- RIR 录音缓冲区提前写入，减少首次回调触发内存页分配的负担。
- 新建配置的 block_size 默认 0，由驱动选择块大小；已保存配置的明确设置不被覆盖。高延迟模式仍保留。
- 结果增加 `xrun_callback_count`、`first_xrun_callback`、`last_xrun_callback`，便于区分启动异常和中途丢帧。已有 xrun 质量检查仍然生效，不会静默当作正常训练数据。

这些修复针对代码中可定位的实时线程和绘图开销；**尚未在用户报告异常的实验室 RME/ASIO 设备上复现或验收，不能保证异常声已经消失**。设备、驱动、采样率转换、不同设备时钟仍可能导致异常。

回调限制及自动块大小选择参考 sounddevice 官方说明：
https://python-sounddevice.readthedocs.io/en/latest/api/streams.html
